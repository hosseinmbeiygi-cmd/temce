# 00_README_HANDOFF — راهنمای تحویل به Claude Code

> این بسته نتیجه‌ی ممیزی مرحله ۰ (بک‌تست و ML مخزن `temce`) را به یک برنامه‌ی اصلاح مرحله‌ای تبدیل می‌کند.
> همه‌ی اسناد مرجع شما (`ARCHITECTURE.md`, `SPEC_*.md`, `CLAUDE.md`, `PHASES_AND_PROMPTS.md`) بر این بسته مقدم‌اند؛ در تعارض: `CLAUDE.md` ← `SPEC_*` ← `ARCHITECTURE.md` ← این بسته.

## ۱. جای فایل‌ها در ریشه‌ی ریپو

```
temce/
  CLAUDE.md                      # فایل خودتان؛ محتوای CLAUDE_ADDENDUM.md را به انتهایش اضافه کنید
  ARCHITECTURE.md  SPEC_*.md  PHASES_AND_PROMPTS.md      # فایل‌های خودتان
  SPEC_DATA_SCHEMAS.md           # از این بسته (پیش‌نویس؛ قبل از اتکا با نمونه واقعی تطبیق شود)
  AUDIT_STAGE0.md                # از این بسته (خلاصه‌ی ممیزی)
  REMEDIATION_PLAN.md            # از این بسته
  CLAUDE_CODE_PROMPTS.md         # از این بسته (پرامپت هر گام)
  BASELINES.md  ADR_DRAFTS.md    # از این بسته
  acceptance.yaml                # قالب خالی؛ فقط شما پر می‌کنید
  rules/rules_template.csv       # قالب جدول قوانین (مقادیر خالی)
  rules/RULES_COLLECTION_GUIDE.md
  audit/REPORT_FULL.md  audit/findings_new.csv    # شواهد خام ممیزی (مرجع، نه دستور)
```

## ۲. وضعیت فعلی

- مرحله ۰ (ممیزی) انجام شده. حکم: **غیرقابل‌اتکا** (اعتبار اندازه‌گیری خراب است؛ مسیر ML صفر است؛ داده و کنترل‌ها معیوب‌اند).
- **دروازه‌ی عبور به گام‌های اصلاح** (طبق `PHASES_AND_PROMPTS.md` مرحله ۰): شما جدول حفظ/بازنویسی/تعلیق در `AUDIT_STAGE0.md` را تأیید کنید و سوال‌های باز را پاسخ دهید.

## ۳. تصمیم‌هایی که فقط شما می‌گیرید (قبل از شروع)

1. **موتور مرجع گزارش‌ها:** پیشنهاد در `ADR_DRAFTS.md` (ADR-001). تأیید یا رد کنید.
2. **ستون تاریخ معامله (`trade_date`)** و معنای `gregorian_date`: ADR-002.
3. **`acceptance.yaml`**: عددها را شما بنویسید، قبل از اولین اجرای مدل. Claude Code حق تغییرش را ندارد.
4. **منابع رسمی قوانین بازار**: اطلاعیه‌ها (دامنه نوسان، حجم مبنا، کارمزد، مالیات، ساعت، تسویه، تعطیلی‌ها). بدون آن هر نتیجه «غیرقابل‌اتکا» می‌ماند (`rules/RULES_COLLECTION_GUIDE.md`).
5. **نرخ‌های مرجع:** نرخ ارز مرجع، نرخ بدون ریسک، شاخص تورم و تأخیر انتشارش (`acceptance.yaml` بخش `reference_rates`).
6. **`SPEC_STRATEGIES.md`**: در فایل‌های آپلودشده نبود. اگر دارید در ریشه بگذارید؛ در غیر این صورت `BASELINES.md` فعلاً جایگزین نیازهای بک‌تست پایه است.

## ۴. نحوه‌ی اجرا با Claude Code

- هر گام از `CLAUDE_CODE_PROMPTS.md` را **در یک جلسه‌ی جدید** بدهید. پایان هر گام Claude Code متوقف می‌شود؛ گزارش را بخوانید، تأیید کنید، بعد گام بعد.
- ترتیب مطالعه در ابتدای هر جلسه: `CLAUDE.md` ← `AUDIT_STAGE0.md` ← بخش مربوط در `REMEDIATION_PLAN.md` ← SPEC مربوط ← گزارش گام قبل.
- تغییر روی فایل‌های موجود فقط به‌صورت **patch (diff) در `patches/`**؛ اعمالشان با تأیید شماست (طبق `CLAUDE.md`). کد جدید در `src/` و `tests/`.
- **هر یافته‌ی ممیزی را Claude Code باید قبل از اقدام خودش بازتأیید کند** (باز کردن فایل:خط، اجرای آزمون). ممیزی با یک مدل دیگر انجام شده و من خودِ کد را ندیده‌ام.

## ۵. ایمنی

- Claude Code به `.env*` (شامل `.env.bak.*`, `.env.production`) دسترسی خواندن نداشته باشد (در تنظیمات مجوزهای ابزار ببندید).
- دیتابیس: فقط کاربر **فقط‌خواندنی** یا کپی ایزوله؛ هر migration فقط به‌صورت فایل SQL پیشنهادی، نه اجرا.
- قبل از شروع: پشتیبان کامل DB و `git tag pre-remediation`.
- در ممیزی ۶ کلید حساس روی دیسک دیده شد (فقط نام؛ در git نیستند). اسکن تاریخچه‌ی git برای رمز هنوز انجام نشده.

## ۶. چیزهایی که این بسته وعده نمی‌دهد

- سودآوری هیچ استراتژی.
- درستی عددی هیچ قانون بازار (همه‌ی مقادیر قانون در این بسته خالی‌اند).
- اینکه سیگنال ML لبه دارد یا نه؛ این هنوز **ناشناخته** است، نه رد شده.
