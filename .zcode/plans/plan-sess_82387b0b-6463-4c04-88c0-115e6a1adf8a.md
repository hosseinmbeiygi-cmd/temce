اصلاح حداقلی صفحه `/markets/gold` و مسیر legacy `/multi-asset`:

1. `frontend/src/app/markets/gold/page.tsx`
   - ادغام WebSocket را از `Object.entries(wsPrices)` به iteration روی `Map` اصلاح می‌کنم؛ فقط وقتی اتصال WebSocket فعال است مقدار آن روی REST بنشیند تا دادهٔ باقی‌ماندهٔ WS بعد از قطع اتصال قیمت تازهٔ REST را override نکند.
   - وضعیت sync را با قرارداد backend هماهنگ می‌کنم: `ok` سالم، `stale`/`outdated` قدیمی، `missing`/`unknown` ناموجود، `error` خطا. برچسب hero و HealthCard دیگر `ok` را قدیمی نشان نمی‌دهند.
   - برچسب `POLLING · stale` را به وضعیت واقعی fallback تغییر می‌دهم؛ REST موفق ولی WS قطع، «polling / آخرین دریافت» نمایش می‌دهد، نه stale قطعی.
   - دکمه‌های تب‌های طلا/سهام/کریپتو/پورتفولیو و بازهٔ نمودار را با `type="button"`، `aria-selected`/`role="tab"` و `data-state` پایدار اصلاح می‌کنم تا تعامل واقعی و تست‌پذیری درست شود.
   - portfolio را از subscription تکراری live حذف می‌کنم؛ همان دادهٔ live صفحه را به `PortfolioModule` پاس می‌دهم.
   - محاسبهٔ BUY/SELL را بر اساس ترتیب زمانی انجام می‌دهم و میانگین قیمت خرید را weighted نگه می‌دارم؛ مقدار hero نیز از همان positions/fund cache استفاده می‌کند تا فروش و صندوق‌ها درست محاسبه شوند.

2. `frontend/src/hooks/useWebSocket.ts`
   - هنگام `onclose`/قطع اتصال، قیمت‌های WS را پاک می‌کنم تا snapshot stale باقی نماند.

3. `frontend/src/lib/market.ts`
   - `weeklyCloses` را با bucket هفتهٔ تقویمی بر اساس تاریخ جایگزین می‌کنم؛ آخرین close هر هفته نگه داشته می‌شود، نه chunk ثابت پنج‌تایی.

4. تست‌ها
   - یک تست کوچک Vitest برای `weeklyCloses` با تعطیلی/فاصلهٔ داده اضافه می‌کنم.
   - تست صفحه/کامپوننت برای تغییر تب و بازهٔ نمودار و mapping وضعیت `ok` اضافه یا در تست موجود تکمیل می‌کنم.
   - `npm --prefix frontend run test -- --run` و lint/type checks را اجرا می‌کنم.

5. بررسی نهایی
   - diff را فقط روی فایل‌های مرتبط نگه می‌دارم.
   - صفحه را روی پورت فعال مرورگر دوباره بازبینی می‌کنم: status تازه، تب‌ها، دکمهٔ هفتگی، و نبود پیام stale کاذب.
