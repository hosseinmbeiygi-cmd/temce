### Design تصمیمات کلیدی

1. **DB مشترک** با `apps/api` و `apps/admin` — همان `core.database.engine`، جدول در schema `currency_service.manual_positions` (یا prefix نام `currency_manual_positions` بسته به migration). بدون engine دوم.
2. **Mock داده** — `infra/fixtures.py` نرخ‌های پایه را از env override می‌گیرد (`CURRENCY_OVERRIDE_JSON`)؛ در غیاب، snapshot پیش‌فرض:
   ```
   free.buy=614500  free.sell=615000  free.daily_change=+1.2
   official.cbi=315000  nima=345000
   usdt.buy=619000  usdt.sell=620000  usdt.daily_change=+1.4
   ```
   هر فراخوانی ±0.3% jitter اعمال می‌کند (پارامتریک از `CURRENCY_JITTER_PCT`).
3. **محاسبات pure** در `domain/pricing.py` و `domain/signals.py` — قابل تست بدون I/O، بدون وابستگی به fixture.
4. **Signal generator منطق سادهٔ heuristic** (نه ML، چون prompt نگفته ML):
   - اگر bubble < 30 و volatility < 2 → BUY MEDIUM
   - اگر tether_arbitrage > +2 → SELL USDT LOW
   - در غیر این صورت NO_SIGNAL
5. **Kill-Switch** = 5 قانون پرامپت دقیقاً (volatility>5%، bubble>150%، spread>3%، |tether arb|>5%، hourly>2%).
6. **Alert dispatcher** log-only به‌صورت پیش‌فرض؛ اگر `TELEGRAM_BOT_TOKEN` در env باشد، `httpx` async call (طبق الگوی موجود) — فعلاً بدون env واقعی.
7. **ردپای صفر در apps/api**: سرویس کاملاً مستقل، router در `apps/api/router.py` اصلاح نمی‌شود (این را صریح می‌گویم چون قبلاً سؤال شد).

### API اندپوینت‌ها

| Method | Path | Auth | توضیح |
|---|---|---|---|
| GET | `/api/v1/currency/overview` | optional | snapshot + arbitrage_matrix + signals + kill_switch |
| GET | `/api/v1/currency/signals` | optional | فقط آرایه signals |
| POST | `/api/v1/currency/positions` | required user | `{asset_type, entry_price, volume}` |
| GET | `/api/v1/currency/positions` | required user | لیست با PnL فعلی |
| DELETE | `/api/v1/currency/positions/{id}` | required user | حذف |
| GET | `/api/v1/currency/health` | none | service + DB + Redis status |
