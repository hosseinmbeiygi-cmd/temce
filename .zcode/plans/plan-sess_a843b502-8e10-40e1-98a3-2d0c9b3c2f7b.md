## استراتژی کلی

**اصل راهنما**: `YAGNI + Stdlib-first + حذف > افزودن`. هر فاز یک اسکور «کیفیت ۱۰۰٪» قابل‌اندازه‌گیری تولید می‌کند (lint 0 / type 0 / test pass / coverage target / secrets 0 / a11y 0). تغییرات **رفتار-خنثی** مگر جایی که گزارش‌های موجود (AUDIT/HIDDEN_ERRORS) باگ بحرانی تأییدشده ثبت کرده باشند.

## فازبندی ۶ فازه (هر فاز = یک PR منطقی)

### فاز ۰ — پاکسازی فوری (نیم‌روز)
**هدف**: حذف آلودگی‌های شناخته‌شده بدون تغییر رفتار.

- حذف `scripts/_*.py` و `scripts/*.json` که debug/tmp هستند (۲۲ فایل). قبل از حذف: بررسی که import نشده باشند.
- حذف `*.log` و `nul` و فایل‌های build artifact در ریشه (`tsconfig.tsbuildinfo`، `pytest-logs/`)
- پاکسازی `.env.local` (اگر secrets واقعی دارد، فقط `.gitignore` محکم‌تر)
- `git rm` با `--cached` برای فایل‌های حساس
- **خروجی**: diff سبک، ۰ خط کد تجاری تغییر

### فاز ۱ — امنیت و Secret Hygiene (۱ روز)
**هدف**: صفر secret plaintext در ریپو، اسکن خودکار.

- `docker-compose.decision-engine.yml`: `POSTGRES_PASSWORD=decision_pass_456` و `de_redis_pass_789` → `${POSTGRES_PASSWORD:?...}` از `.env` (که در `.gitignore`)
- `k8s/decision-engine-secret.yaml`: مهاجرت به `stringData: {}` خالی + سند `sealed-secrets`/`external-secrets`
- `docker-compose.production.yml`: فایل‌های `./secrets/*.txt` → نمونه `./secrets/.example.txt` و `.gitignore` محکم
- اضافه‌کردن `.github/workflows/secrets-scan.yml` با `gitleaks`
- اضافه‌کردن `pre-commit` hook (gitleaks + ruff + eslint)
- حذف `decision_pass_456` و `de_redis_pass_789` از git history با `git filter-repo` (نیاز به force-push → هشدار)
- **خروجی**: `gitleaks detect` → 0؛ همه secrets از env

### فاز ۲ — Type Safety Backend (۲ روز)
**هدف**: mypy روی همه فایل‌های `.py` بدون `ignore_errors`.

- تنظیم `[tool.mypy]`: `strict = true` global، `ignore_missing_imports = true` (برای third-party)
- حذف همه `[[tool.mypy.overrides]]` که `ignore_errors = true` دارند (۷ ماژول legacy)
- افزایش تدریجی: ابتدا `apps/api/endpoints/` و `brsapi/services/` (پرکاربرد)، سپس `services/`
- رفع `Any` ها: جایگزینی با `TypedDict` / `Generic[T]` / `Protocol` / `from typing import ...` صریح
- الگوهای هدف:
  - توابع بدون return type → اضافه‌کردن
  - `Optional[X]` → `X | None` (py3.10+)
  - `Dict`/`List` → `dict`/`list` (PEP 585)
- CI: حذف `|| true` از mypy در `ci.yml:94`
- **خروجی**: `mypy --strict` روی `apps/`, `brsapi/`, `services/`, `domain/` → 0 خطا

### فاز ۳ — Lint/Format پاک (۱ روز)
**هدف**: ruff 0 error، حذف ignoreهای غیرضروری.

- کوچک‌سازی `[tool.ruff.lint] ignore`: حذف `E501` (wrap logic)، `B008` (FastAPI Depends)، `B027` (empty method in ABC)، `B904` (raise from)، `SIM102` (nested if) یکی‌یکی پس از رفع
- اجرای `ruff check --fix` و `ruff format` روی همه
- حذف per-file-ignores که legacy شده‌اند
- pre-commit hook برای `ruff format` + `ruff check` + `mypy`
- CI: حذف `continue-on-error: true` از benchmark و frontend در `ci-pr.yml`
- **خروجی**: `ruff check .` → 0؛ `ruff format --check` → diff صفر

### فاز ۴ — Frontend Quality (۲ روز)
**هدف**: ESLint 0، TypeScript strict، a11y پایه.

- `frontend/tsconfig.json`: `strict: true`، `noUncheckedIndexedAccess: true`، `exactOptionalPropertyTypes: true`
- `frontend/eslint.config.mjs`: فعال‌سازی `@typescript-eslint/no-explicit-any` به‌عنوان error
- حذف همه `eslint-disable` با refactor (۲۳ فایل)
- جایگزینی `useEffect` های anti-pattern (data fetching → react-query، setState in render → memo/derived)
- a11y: همه `<img>` → `next/image` با `alt`، همه `<button>` بدون `aria-label` → اضافه، focus states
- حذف `alert()` و `confirm()` → `sonner` toast (که از قبل نصب است)
- `'use client'` فقط در صورت نیاز
- `next.config.ts`: فعال‌سازی `output: 'standalone'` (اگر Dockerfile.frontend لازم دارد) + verify
- **خروجی**: `tsc --noEmit` → 0؛ `eslint . --max-warnings=0` → 0

### فاز ۵ — تست منطق حساس (۲ روز)
**هدف**: coverage هدفمند فقط روی ماژول‌های مالی/ریسک/امنیت.

اولویت تست (بر اساس گزارش‌های HIDDEN_ERRORS و AUDIT):

- CI: `pytest --cov=apps --cov=brsapi --cov=services --cov-fail-under=60` (آغاز با ۶۰٪ روی ماژول‌های هدف)

**هدف**: container امن، CI کامل، مستندات ساخت‌یافته.

## ریسک‌ها

1. **mypy strict روی کل کد**: ۸۰٪ ignore شده، ممکن است ۵۰۰+ خطا یکجا. → استراتژی: فازبه‌فاز، با `disable_error_code` برای دسته‌های خاص به‌جای ignore کل ماژول
2. **حذف فایل‌های `_tmp_*.py`**: ممکن است یکی import شده باشد. → قبل از حذف: `grep -r` برای import
3. **force-push برای پاکسازی git history**: نیاز به همکاری همه contributor. → اگر نمی‌پذیرید، فقط `.env.example` با placeholder
4. **Frontend refactor ۷۰K LOC**: ممکن است hydration/react-query refactor زمان ببرد. → صفحه‌به‌صفحه با regression test
5. **افزایش coverage به ۶۰٪**: برخی ماژول‌ها (ml، ingestion) ذاتاً نیاز به integration test دارند. → فقط ماژول‌های pure/financial
