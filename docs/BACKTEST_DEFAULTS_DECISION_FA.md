## ۴) حکم — ۲۸ ردیف باقی‌مانده (۲۷ عددی + `mode`): تنظیم یا نام‌گذاری، نه باگ

۲۸ نام غیرعددیِ باقی‌مانده از مجموع ۶۰ (مثل `status`, `seed`, `method`, `name`, `side`, `date`, `market`,
`symbol`, `regime`, `cost_model`, `ttl_seconds` و ...) enum/رشته‌اند و در محاسبهٔ پول جای هم نمی‌نشینند؛
حکمشان همان **N (نام‌گذاری)** است: هیچ‌کدام نباید به‌عنوان «پیش‌فرض مشترک» به `defaults.py` منتقل شوند.

این‌ها در محاسبهٔ پول جای هم نمی‌نشینند: هر کدام یک «ولوم تنظیم» در یک ماژول متفاوت است یا واحد متفاوتی از یک پدیده. حکم برای هرکدام یکی از این دو است:

- **N — نام‌گذاری:** نام عمومی است و در دو ماژول دو معنا دارد؛ باید اختصاصی شود (`window` → `rolling_window_days`).
- **C — کالیبراسیون:** انتخاب مهندسی/آماری است؛ تعارض واقعی نیست، ولی باید در یک فایل کانفیگ متمرکز و مستند شود.

### قاعدهٔ نام‌گذاری (برای جلوگیری از تعارض جعلی)

1. پارامتر پیش‌فرض‌دار فقط وقتی نام عمومی می‌گیرد که **همان کمیت با همان واحد** در کل مسیر بک‌تست باشد.
2. هر پارامتر پولی/درصدی باید **واحد در نام** داشته باشد: `_pct` (کسر ۰..۱)، `_bps`، `_rial`، `_tomans`.
3. هر پارامتر پیش‌فرض‌دار باید در `backtesting/config/defaults.py` یک ردیف داشته باشد؛ مقدار محلی در تابع ممنوع.

اسکریپت بند ۲ (تعارض‌نگار):

```python
# اسکریپت تعارض‌نگار — json مسیر بک‌تست را می‌خواند و نام‌های متناقض را می‌شمارد
import json, sys
from collections import defaultdict
from decimal import Decimal, InvalidOperation

def norm(value: str):
    try:
        return format(Decimal(value).normalize(), "f"), True   # عدد نرمال‌شده
    except (InvalidOperation, ValueError):
        return value.strip().lower(), False                    # غیرعددی

def conflicts(path: str, numeric_only: bool):
    data = json.load(open(path, encoding="utf-8"))
    by_param = defaultdict(lambda: defaultdict(list))
    for fn in data["functions"]:
        for param, value in fn["defaults"].items():
            key, is_num = norm(value)
            if numeric_only and not is_num:
                continue
            by_param[param][key].append(f"{fn['file']}:{fn['line']}")
    if numeric_only:   # نام‌هایی که بعضی مقدارهایشان غیرعددی است را کنار بگذار
        for param in list(by_param):
            if any(not norm(v)[1] for v in by_param[param]):
                del by_param[param]
    return {p: dict(v) for p, v in by_param.items() if len(v) > 1}

if __name__ == "__main__":
    path = "audit_out/_logs/backtest_parameters_full.json"
    for flag in (False, True):
        c = conflicts(path, flag)
        print(("numeric-only" if flag else "all values"), "->", len(c), "conflicting parameter names")
```

## ضمیمه — یافتهٔ بازِ امروز (خارج از موضوع پیش‌فرض‌ها، از خودِ اجرای تست‌ها)

**شکست خاموش در ذخیرهٔ نتیجهٔ بک‌تست.** حین اجرای مسیر بک‌تست (۱۴۰۴/۰۷/۲۰)، در ۷۴۵ فراخوانی این لاگ ثبت شد و در کنارش پاسخ `POST /api/v1/backtests/run -> 200` آمد:

```
[warning] Failed to persist backtest result: Session is already flushing
[warning] Failed to persist backtest result: object MagicMock can't be used in 'await' expression   (۱ مورد، از mock تست)
```

- محل: `services/backtest_service.py:397-399` — استثنای ذخیره‌سازی فقط **لاگ warning** می‌شود.
- بلافاصله بعدش (خط ۴۰۱) همان تابع `Result.ok(... status="completed", progress_pct=100.0 ...)` برمی‌گرداند.
- پیامد: API می‌گوید «تمام شد» ولی `BacktestRun` ذخیره نشده ⇒ تاریخچهٔ بک‌تست خالی/ناهمگون می‌شود. این با «مسیر بک‌تست صفر خطا»ی تست‌ها تضاد ندارد، چون هیچ تستی ذخیره‌شدن را بررسی نمی‌کند.
- پیشنهاد (گام بعدی فاز A، C1): یا `save` قبل از فلاش/در سشن مستقل، یا بازگرداندن `Result.fail`/`status="persisted": false` به‌جای موفقیت خاموش + تستی که پس از اجرا، وجود ردیف را می‌سنجد.
- اثر GCI: بدون این، هر ادعای «بک‌تست اجرا شد» شاهد پایدار ندارد.
